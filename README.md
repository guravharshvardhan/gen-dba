
# Gen-DBA + GenStore
### AI-Assisted Database Performance Analysis and E-commerce Workload Demonstration

## 📌 Overview

Gen-DBA is an AI-assisted database performance analysis project designed to identify potential SQL query bottlenecks, analyze query execution plans, evaluate performance risks, and provide optimization recommendations.

GenStore is a companion e-commerce demonstration application that generates realistic database workloads through product browsing, category navigation, and customer search.

Both applications are designed to connect to the same PostgreSQL database, `gendba`, allowing Gen-DBA to inspect database workload generated by GenStore.

The project demonstrates how application-level database activity can be connected with query analysis and optimization recommendations through a unified workflow.

> **Project Status:** Academic and demonstration prototype. Features should be verified against the running implementation. AI-generated recommendations are advisory and require human review.

## 🚀 Key Features

### 1. SQL Query Analysis
- Analyze query execution-plan information where supported.
- Identify potential sequential scans, expensive joins, and high row-processing costs.
- Organize query findings for further investigation.

### 2. Workload Analysis
- Generate database activity through GenStore.
- Record relevant workload in the `query_logs` table when logging succeeds.
- Make workload available for inspection through Gen-DBA.

### 3. AI-Assisted Recommendations
- Integrate AI-assisted recommendation functionality through the Gen-DBA backend.
- Provide explanations and potential optimization suggestions.
- Support human review before applying suggested changes.

### 4. Risk and Impact Scoring
- Use scoring modules to help prioritize potential database issues.
- Support the review of findings based on their assessed severity and impact.

### 5. Query Comparison and Optimization
- Include modules for query comparison and optimization-related workflows.
- Support investigation of performance improvements where the corresponding functionality is implemented and configured.

### 6. GenStore E-commerce Demo
- Product and category browsing.
- Product search.
- Customer search.
- PostgreSQL-backed API operations.
- Workload generation for database analysis.

### 7. Shared PostgreSQL Integration
- Configure both backends to use the same PostgreSQL database.
- Use GenStore-generated workload as an input for Gen-DBA analysis.

## ⚙️ Installation and Setup

### 📋 Prerequisites

Before running the project, ensure that the following are installed:

- Python and pip
- Node.js and npm
- PostgreSQL
- pgAdmin or another PostgreSQL client
- Visual Studio Code
- Git (recommended)

AI functionality may also require valid API credentials, depending on the configured implementation.

### Step 1: Database Setup

1. Start the PostgreSQL service.
2. Open pgAdmin and connect to the server.
3. Select the `gendba` database.
4. Review the SQL file:

   `gen-store/database/gen_store_upgrade.sql`

5. Run the script against the intended development database after reviewing its contents.
6. Verify that all required tables and columns exist.

Back up important data before running schema changes.

### Step 2: Configure Environment Variables

Configure the `.env` files for both backends using the variable names expected by their source code.

Example database configuration:

```dotenv
DB_HOST=localhost
DB_PORT=5432
DB_NAME=gendba
DB_USER=your_postgres_user
DB_PASSWORD=your_postgres_password
```

Replace the placeholders with your local PostgreSQL credentials.

**Important:** Both applications must connect to the same database for GenStore-generated workload to be visible to Gen-DBA.

Never commit real database passwords or API keys to GitHub.

## 🔎 Example Database Optimization Candidate

The GenStore customer-search workflow uses a query pattern similar to:

```sql
SELECT user_id, name, email, city, created_at
FROM users
WHERE LOWER(city) = LOWER(%s)
ORDER BY user_id DESC
LIMIT 25;
```

Applying a function such as `LOWER()` to a column can prevent a conventional index on that column from being used for the filter as expected.

This query can be investigated as a potential optimization candidate using the actual execution plan, existing indexes, and representative data.

An index is not guaranteed to improve every query. Any optimization should be tested before implementation.

## 🛠️ Troubleshooting

### Database Offline

If GenStore displays `Database Offline`:

1. Open `http://127.0.0.1:8010/api/health`.
2. Check the GenStore backend terminal for database errors.
3. Confirm PostgreSQL is running.
4. Verify database credentials in the GenStore `.env` file.
5. Confirm the database name is `gendba`.
6. Verify the required tables and columns.

### CORS Error

If the browser reports a CORS error:

1. Check the exact frontend origin and port in the address bar.
2. Add the origin to the existing `CORSMiddleware` `allow_origins` list in the relevant backend.
3. Save the file and confirm that Uvicorn reloads.
4. Refresh the browser using `Ctrl + Shift + R`.

For example, if GenStore runs on port `5177`, include:

```python
"http://localhost:5177",
"http://127.0.0.1:5177",
```

Do not create unnecessary duplicate CORS middleware blocks.

### Port Already in Use

Vite may automatically choose another available port. Use the actual Local URL printed in the terminal and ensure the backend allows that origin.

### Workload Not Visible in Gen-DBA

- Confirm both applications use the same PostgreSQL database.
- Confirm the request reaches the GenStore backend.
- Check whether the insert into `query_logs` succeeds.
- Confirm Gen-DBA reads from the expected table and schema.

### Backend Startup Error

- Confirm the terminal is in the correct directory.
- Activate the correct virtual environment.
- Install missing dependencies.
- Check the first traceback in the terminal.
- Verify that the selected port is available.

## 🔐 Security and Limitations

- This project is an academic/demo prototype, not a production-certified database administration platform.
- AI-generated recommendations are advisory and must be reviewed.
- The Gen-DBA interface has displayed a message that approval is disabled for safety. Do not assume approval or automatic execution is enabled merely because related modules exist.
- Keep `.env` files and API keys private.
- Use a development database and maintain backups before schema changes.
- Validate query changes using execution plans and representative workloads.
- Verify authentication, authorization, audit logging, and rollback behavior before production deployment.
- Successful server startup alone does not prove that the complete integration is working.
